[[overview]]
== 概況

在使用 Trident 配置磁碟區之前，您需要透過建立 Trident Backend Configuration（TBC）將儲存後端與 Trident 整合。TBC 定義了 Trident 如何連接到儲存後端，並提供 Trident 管理儲存資源所需的必要資訊。



[[create-a-trident-backend-configuration-tbc-for-fsx-for-ontap]]
== 為 FSx for ONTAP 建立 Trident 後端組態（TBC）

有兩種方法可以設定 Trident 後端以使用 FSx for ONTAP 檔案系統：* 建立一個利用自動後端功能的 StorageClass。* 分別建立後端和 StorageClass。

本節中的步驟涵蓋如何單獨建立後端。有關如何使用自動後端功能的資訊，請參閱link:trident-fsx-storageclass-pvc.html#configure-a-storage-class-without-automatic-backend-configuration["配置 StorageClass 和 PVC"]章節以取得更多資訊。

若要建立儲存後端，您需要建立 JSON 或 YAML 格式的組態檔。該檔案需要指定所需的儲存類型（NAS 或 SAN）、檔案系統、要從中取得資料的 SVM 以及如何進行驗證。以下範例展示如何定義基於 NAS 的儲存，以及如何使用 AWS Secret 來儲存要使用的 SVM 的憑證：

[role="tabbed-block"]
====
.YAML
--
[source, YAML]
----
apiVersion: trident.netapp.io/v1
kind: TridentBackendConfig
metadata:
  name: backend-tbc-ontap-nas
  namespace: trident
spec:
  version: 1
  storageDriverName: ontap-nas
  backendName: tbc-ontap-nas
  svm: svm-name
  aws:
    fsxFilesystemID: fs-xxxxxxxxxx
  credentials:
    name: "arn:aws:secretsmanager:us-west-2:xxxxxxxx:secret:secret-name"
    type: awsarn
----
--
.JSON
--
[source, JSON]
----
{
  "apiVersion": "trident.netapp.io/v1",
  "kind": "TridentBackendConfig",
  "metadata": {
    "name": "backend-tbc-ontap-nas"
    "namespace": "trident"
  },
  "spec": {
    "version": 1,
    "storageDriverName": "ontap-nas",
    "backendName": "tbc-ontap-nas",
    "svm": "svm-name",
    "aws": {
      "fsxFilesystemID": "fs-xxxxxxxxxx"
    },
    "managementLIF": null,
    "credentials": {
      "name": "arn:aws:secretsmanager:us-west-2:xxxxxxxx:secret:secret-name",
      "type": "awsarn"
    }
  }
}

----
--
====
執行下列命令以建立和驗證 Trident Backend Configuration（TBC）：

* 從 yaml 檔案建立 Trident 後端組態（TBC），並執行下列命令：
+
[source, console]
----
kubectl create -f backendconfig.yaml -n trident
----
+
[listing]
----
tridentbackendconfig.trident.netapp.io/backend-tbc-ontap-nas created
----
* 驗證 Trident 後端組態（TBC）是否已成功建立：
+
[source, console]
----
Kubectl get tbc -n trident
----
+
[listing]
----
NAME                         BACKEND NAME         BACKEND UUID                           PHASE   STATUS

backend-tbc-ontap-nas        tbc-ontap-nas        933e0071-66ce-4324-b9ff-f96d916ac5e9   Bound   Success
----




[[fsx-for-ontap-driver-details]]
== FSx for ONTAP 驅動程式詳細資料

您可以使用下列驅動程式將 Trident 與 Amazon FSx for NetApp ONTAP 整合：

* `ontap-san`：每個已配置的 PV 都是其自身 Amazon FSx for NetApp ONTAP 磁碟區中的一個 LUN 。建議用於區塊儲存設備。
* `ontap-nas`：每個已配置的 PV 都是一個完整的 Amazon FSx for NetApp ONTAP 磁碟區。推薦用於 NFS 和 SMB。
* `ontap-san-economy`：每個已配置的 PV 都是一個 LUN，每個 Amazon FSx for NetApp ONTAP 磁碟區可設定 LUN 的數量。
* `ontap-nas-economy`：每個已配置的 PV 都是一個 qtree，每個 Amazon FSx for NetApp ONTAP 磁碟區可配置的 qtree 數量。
* `ontap-nas-flexgroup`：每個已配置的 PV 都是一個完整的 Amazon FSx for NetApp ONTAP FlexGroup 磁碟區。


有關驅動程式詳細資料、請參閱 link:../trident-use/ontap-nas.html["NAS 驅動程式"] 和 link:../trident-use/ontap-san.html["SAN 驅動程式"] 。

設定檔建立完成後，執行以下命令將其建立在 EKS 中：

[source, console]
----
kubectl create -f configuration_file
----
若要驗證狀態、請執行此命令：

[source, console]
----
kubectl get tbc -n trident
----
[listing]
----
NAME                    BACKEND NAME            BACKEND UUID                           PHASE   STATUS
backend-fsx-ontap-nas   backend-fsx-ontap-nas   7a551921-997c-4c37-a1d1-f2f4c87fa629   Bound   Success
----

== 配置 SMB Volume

您可以使用  `ontap-nas` 驅動程式來配置 SMB 磁碟區。在完成 link:trident-fsx-storage-backend.html#fsx-for-ontap-driver-details["ONTAP SAN 和 NAS 驅動程式整合"] 之前，請先完成以下步驟：link:worker-node-prep.html#prepare-to-provision-smb-volumes["準備配置 SMB Volume"]
