== 26.06.2 版本新增內容

了解 NetApp Trident 和 Trident Protect 的新特性，包括增強功能、修復和棄用。



[[trident]]
=== Trident



==== 增強功能

* *Kubernetes*：
+
** 新增對 Kubernetes 1.37 的支援。






==== 修復

* *Kubernetes*：
+
** 修正了當 Trident 控制器重新啟動或更新 `TridentBackendConfig`，且 `enableConcurrency`設定為 `true`時，ONTAP-NAS 匯出原則規則會被靜默刪除的問題。這可能會使已掛載的 Volume 處於停滯狀態（link:https://github.com/NetApp/trident/issues/1166["問題 #1166"]，link:https://github.com/NetApp/trident/issues/1179["問題 #1179"]）。
** 修正了後端更新針對非實質變更（例如憑證和 QoS）執行每個 Volume 孤立掃描的問題，這可能會在大型後端上區塊 CSI 操作數小時。現在，該掃描僅在 SVM 或儲存設備前綴發生變更時執行。
** 修正了 Trident 偵錯日誌中出現的憑證問題，包括 CSI gRPC 請求轉儲、啟動環境轉儲以及  `TridentBackendConfig` CRD 控制器記錄的規格。啟動環境轉儲現在只記錄 Trident 自身  `TRIDENT_*` 變數的值，並按名稱列出其他變數。

** 新增在啟用並行功能的情況下執行 Trident 時，對磁碟區更新和磁碟區群組快照的支援。
** 為 GCNV 新增動態 gRPC 速率限制。
** 新增了控制器就緒執行探測，並調整了控制器和邊車的預設 Kubernetes API QPS 和 Burst 設定。
** 改進節點操作順序，將附加、加密設定和檔案系統格式化步驟解耦。
** 將 Trident 容器根檔案系統掛載為唯讀，以提高安全性。
** 在 ONTAP 後端中，當複製磁碟區的來源快照被刪除時，會盡力刪除複製磁碟區快照。

** 防止 ONTAP-SAN-ECONOMY 驅動程式在調整大小操作期間 Flexvols 縮小。

** 修正了當可用路徑和入口網站不符時發生的 iSCSI 調整大小失敗問題，並改善了重複調整大小的行為。

=== Trident Protect



==== 增強功能

* 新增了 OpenShift Service CA Operator 整合，用於自動化 Trident Protect 准入 Webhook 的 TLS 憑證管理。可透過在 Helm 值中將 `useOpenshiftServiceCA`設定為 `true`來啟用。若要深入瞭解，請參閱 link:trident-protect/trident-protect-customize-installation.html["自訂 Trident Protect 安裝"^]。
* 新增在 OpenShift Virtualization 上備份與還原 KubeVirt VM 的支援。保護命名空間中的所有 VM，或依名稱指定特定的 VM，並從備份或快照中選擇性地還原個別 VM。若要深入瞭解，請參閱 link:trident-protect/trident-protect-kubevirt-vms.html["使用 Trident Protect 保護 KubeVirt 虛擬機器"^]。
* 新增了對資源轉換的支援，讓您在還原過程中新增、刪除和修改 Kubernetes 資源屬性。若要深入瞭解，請參閱 link:trident-protect/trident-protect-resource-transformations.html["使用自訂資源還原資源時修改資源"]。
* 新增了對 AppMirrorRelationship （AMR）中 `storageClassMapping`的支援，可在單一 AMR 定義中為各個 PVC 進行儲存類別對應。若要深入瞭解，請參閱 link:trident-protect/trident-protect-use-snapmirror-replication.html["使用 NetApp SnapMirror 和 Trident Protect 複製應用程式"^]。




==== 修復

* 修正了當來源應用程式命名空間在目標叢集上不存在時，跨叢集虛擬機器還原失敗並出現准入 webhook 錯誤的問題。
* 修正了由於與現有應用程式自訂資源的規格不符，導致選擇性虛擬機器就地還原在應用程式建立步驟失敗的問題；現在可重複使用現有應用程式。
* 修正了虛擬機器就地復原作業在虛擬機器及其 PersistentVolumeClaim 均被刪除時停滯於 `Running`狀態的問題；缺少 PersistentVolumeClaim 現在將被視為嚴重錯誤。
* 修正了編輯現有保護排程時錯誤地觸發立即備份或快照執行的問題。
* 修正了快照終結器在應用程式自訂資源被刪除後嘗試獲取該資源的問題；現在，如果找不到應用程式，終結器會跳過此步驟。
* 修正在 PersistentVolumeClaim 複製步驟中使用稀疏複製進行虛擬機器就地還原後，固定保護儲存容量大幅增加的問題。
* 修正了 Trident Protect 在 ONTAP 中確認刪除後端快照之前刪除 Kubernetes 快照物件的問題；現在終結器會等待 `VolumeSnapshot`刪除。
* 修正了虛擬機器凍結操作失敗時快照無法繼續執行的問題；現在凍結和解凍操作在失敗時仍會繼續進行。
* 已修正 KubeVirt 虛擬機器應用程式在 AppMirrorRelationship 反向、反向重新同步和重新同步作業期間，錯誤地重新建立 PersistentVolumeClaims 的問題。

* 修正了在同一秒內執行快照時並發克隆快照操作的問題。
* 修正了阻止使用 `dataVolumes`的 KubeVirt VM 透過 Trident Automated Workload Failover 進行故障轉移的問題。
* 修正了在使用 Trident 並發核心時刪除無效 `TridentMirrorRelationship`自訂資源時發生的錯誤。
* 修正了  `tridentactionmirrorupdates` Kubernetes CRD YAML 定義中的縮排問題（問題 #1120）。
* 修正了 REST qtree 非同步刪除 API 呼叫（Issue #1121）。
* 已修復 `ControllerPublish`，現在使用磁碟區組態檔案系統類型，而不是錯誤的預設檔案系統類型。
* 修正了控制器啟動日誌記錄，使其能夠正確報告並行驅動程式狀態。
* 修正了並發 Trident 中對已暫停後端的處理。
* 增強了 AWS ARN 處理能力，以支援特殊區域。

==== 已知問題

[WARNING]
====
 `csi-snapshotter` sidecar 存在已知問題。在所有 Kubernetes 版本中、VolumeGroupSnapshots `v1beta1` 會阻止 VolumeSnapshots 達到 `ReadyToUse`狀態。

====
有兩種因應措施：

. 刪除 VolumeGroupSnapshots CRD 以停用 VolumeGroupSnapshots，然後重新安裝 Trident。
. 安裝 VolumeGroupSnapshots `v1beta2` 和 `snapshot-controller` 版本 8.4.0 或更高版本，然後重新安裝 Trident。VolumeGroupSnapshots 無法在低於 v1.34 的 Kubernetes 版本上運行。




==== 修復

[[known-issues]]
== 已知問題

已知問題是指可能妨礙您成功使用產品的問題。

* 當將安裝了 Trident 的 Kubernetes 叢集從 1.24 升級到 1.25 或更高版本時，必須先更新 values.yaml 將 `excludePodSecurityPolicy`設定為 `true`或新增 `--set excludePodSecurityPolicy=true`至 `helm upgrade`命令中，然後才能升級叢集。
* Trident 現在會對於在其 StorageClass 中未指定  `fsType` 的磁碟區強制執行空白  `fsType` (`fsType=""`。當使用 Kubernetes 1.17 或更新版本時，Trident 支援為 NFS 磁碟區提供空白  `fsType`。對於 iSCSI 磁碟區，當使用 Security Context 強制執行  `fsGroup` 時，您必須在 StorageClass 上設定  `fsType`。
* 當在多個 Trident 實例中使用相同後端時，每個後端設定檔應該為 ONTAP 後端設定不同的 `storagePrefix`值，或為 SolidFire 後端使用不同的 `TenantName`。Trident 無法偵測到其他 Trident 實例建立的磁碟區。嘗試在 ONTAP 或 SolidFire 後端上建立現有磁碟區都會成功，因為 Trident 將磁碟區建立視為冪等操作。如果 `storagePrefix`或 `TenantName`配置值相同，則在相同後端上建立的磁碟區可能會出現名稱衝突。
* 安裝 Trident（使用 `tridentctl`或 Trident Operator）以及使用 `tridentctl`管理 Trident 時、應確保已設定 `KUBECONFIG`環境變數。這是指定 `tridentctl`應使用的 Kubernetes 叢集所必需的。使用多個 Kubernetes 環境時、應確保 `KUBECONFIG`檔案已正確載入。
* 要對 iSCSI PV 執行線上空間回收，工作節點上的底層作業系統可能需要將掛載選項傳遞給磁碟區。對於 RHEL/Red Hat Enterprise Linux CoreOS (RHCOS) 實例來說尤其如此，它們需要 `discard` https://access.redhat.com/documentation/en-us/red_hat_enterprise_linux/8/html/managing_file_systems/discarding-unused-blocks_managing-file-systems["掛載選項"^]；確保 discard mountOption 包含在您的[`StorageClass`中，以支援線上區塊丟棄。
* 如果每個 Kubernetes 叢集中存在多個 Trident 實例，Trident 將無法與其他實例通信，也無法發現它們建立的其他磁碟區。如果在叢集中執行多個 Trident 實例，則會導致意外的錯誤行為。每個 Kubernetes 叢集應該只有一個 Trident 實例。
* 如果在 Trident 離線期間從 Kubernetes 中刪除了基於 Trident 的 `StorageClass`物件，Trident 在重新上線後不會從其資料庫中刪除相應的儲存類別。您應該使用 `tridentctl`或 REST API 刪除這些儲存類別。
* 如果使用者在刪除相應的 PVC 之前刪除了 Trident 配置的 PV，Trident 不會自動刪除其支援磁碟區。您應該透過 `tridentctl`或 REST API 刪除該磁碟區。
* 除非每個配置請求的聚合集都是唯一的，否則 ONTAP 一次不能同時配置多個 FlexGroup。
* 使用 Trident 透過 IPv6 時，您應在後端定義中以方括號指定 `managementLIF`和 `dataLIF`。例如，``[fd20:8b1e:b258:2000:f816:3eff:feec:0]``。
+

NOTE: 您無法在 ONTAP SAN 後端上指定 `dataLIF`。Trident 會發現所有可用的 iSCSI LIF 並使用它們來建立多路徑工作階段。

* 如果使用 `solidfire-san`驅動程式搭配 OpenShift 4.5，請確保底層工作節點使用 MD5 作為 CHAP 驗證演算法。Element 12.7 提供安全的 FIPS 相容 CHAP 演算法 SHA1、SHA-256 和 SHA3-256。
